# API Keys & Authentication

Every request to the SPL Maps API must carry an API key in a request header. Authentication is per request: there is no login and no session. The same key and header are used for the map styles and for the APIs in the [API reference](/docs/api).

Use the gateway that issued your key. SPL Maps is served through more than one gateway, and they differ in the base URL, the header that carries the key and, for some services, the path.

Use this option if your key was issued for the SPL API gateway.

| Setting | Value |
| --- | --- |
| Base URL | `{{gatewayBase}}` |
| Header | `{{gatewayKeyHeader}}` |

Send your key in the `{{gatewayKeyHeader}}` header on **every** request. The key goes in the header only: the gateway does not accept it as a URL parameter. Map styles:

```bash
curl --location '{{gatewayBase}}/styles/spl_satellite/style.json' \
--header '{{gatewayKeyHeader}}: YOUR_API_KEY'
```

The APIs use the same header and start with `/api/v1/` under the base URL:

```bash
curl --location '{{gatewayBase}}/api/v1/search/autocomplete?q=Riyadh&latitude=24.7136&longitude=46.6753&limit=10' \
--header '{{gatewayKeyHeader}}: YOUR_API_KEY'
```

## What happens when a request is not accepted

The gateway answers with a JSON body that tells you what is wrong, so always look at the message and not only at the status code. A `401` means the key itself is the problem; a `403` means the key is valid but the request is not allowed right now.

| HTTP | Gateway message | Meaning and what to do |
| --- | --- | --- |
| `401` | `Access denied due to missing subscription key. Make sure to include subscription key when making requests to an API.` | No key was sent. Check that the header is present on **every** request, including tiles, fonts and icons. |
| `401` | `Access denied due to invalid subscription key. Make sure to provide a valid key for an active subscription.` | The key is unknown, mistyped or no longer active. Copy it again, and confirm with the SPL team that it is active. |
| `403` | `Out of call volume quota. Quota will be replenished in HH:MM:SS.` | The key is valid but has used up its call volume quota. The message and the `Retry-After` header say when it is replenished. Nothing is wrong with the key: wait, or ask the SPL team for a higher quota. |
| `404` | `Resource not found` | Nothing is served at this address on the gateway. Check the base URL, including its path, and the style ID or API path. |
| `429` | - | The gateway is rate limiting because too many requests were sent too quickly. Pace the requests and retry with a growing delay. |

## Quota and rate limits

Two separate limits apply to a key, and they are easy to confuse because a
map is not one request:

- **Call volume quota** is the number of requests a key may make in a period.
  Loading a map costs many requests: the style, then every map tile, every
  label font file and the icon sheet. A single map view can use dozens of
  requests, so the quota is used up much faster than the number of page views
  suggests. When it is used up, every request returns `403` until the quota is
  replenished.
- **Rate limit** applies to the speed of requests. Sending many requests at
  once is answered with `429`. Keep the number of concurrent requests low and
  retry a `429` after a short delay.

## Using the key in a browser

A map in a web page has to send the key from the browser, so the browser calls
the gateway directly. A browser only allows that when the gateway permits the
website the page is on. The permitted websites are configured on the gateway.

| Where the page runs | Can it call the gateway from the browser? |
| --- | --- |
| A website the gateway permits | Yes |
| Any other website | No. The browser blocks the request before it is sent |
| A file opened from disk (`file://`) | No. The browser blocks the request before it is sent |

A blocked request does not return a status code. The page only reports a
network error, such as `Failed to fetch` in JavaScript. If your website is not
permitted yet, contact the SPL team and give them its address, for example
`https://maps.your-domain.com`. An address used for local testing, such as
`http://localhost:3000`, has to be permitted as well.

Calling the gateway from your own backend is not subject to this rule, because
a backend is not a browser. Let the page call your backend, and let your
backend call the gateway with the key.

Anyone who opens the browser tools of your page can see the key, so a key that
is used in a browser must be treated as public. If the key has to stay secret,
call the gateway from your backend instead.

## Best Practices

1. **Keep keys out of source control**: load the key from an environment variable or a secret store, and never commit it.
2. **Send the key on every request**: authentication is per request. There is no session or login step, and a missing header on tiles or fonts leaves the map blank.
3. **Read the gateway message**: `401` is a key problem, `403` is a quota problem and `404` is an address problem. Each one has a different fix.
4. **Cache what you can**: the style changes rarely, and map tiles are cached by the browser. Do not reload the style on every page view.
5. **Rotate keys carefully**: if a key may have been exposed, contact the SPL team to have it revoked and reissued.
